## 1. 背景与目标

### 1.1 问题

MerakCode 已具备强执行能力（Session、工具、Rules、Memory、Skills、MCP），但产品主路径仍是「打开项目 → 编码会话」。用户缺少一套以**AI 同事**为中心的工作方式：配职责、养知识、聊天派活、看板收口。

### 1.2 目标

在 MerakCode 上落地 **all-chat**：本地优先的 AI 同事工作台。

一句话：

> **配一个同事 → 用文件夹养世界观（职责 / 规则 / 记忆等）→ 聊天派活 → 看板收口。**

### 1.3 非目标（本期明确不做）

以下能力不在本期范围（参考 Autera 有、但与核心闭环无关或可后置）：

- 权限审批会话 / 审批中心 UI
- 通知中心
- 消息附件
- 任务「触发执行」与 Codex 式 Run 详情抽屉
- 主题系统
- 感知信号订阅与自动调度决策层
- 多租户、云端同步、团队 RBAC
- 多 Runtime 编排（Codex CLI / Claude CLI / Mock）；本期 Runtime **仅 MerakCode 引擎 / SDK**

## 2. 用户与场景

### 2.1 典型用户

- 个人开发者 / 小团队负责人：希望多个专职 Agent（研发、研究、运营等）长期协作，而不是每次从空白会话开始。

### 2.2 核心场景

1. **入职一个同事**：创建 Agent，预置世界观目录（职责、规则、记忆等），填写职责说明。
2. **养世界观**：用文件夹管理事实、规则、记忆、决策；内容真实落盘，会话中可被引擎注入或读取。
3. **私聊派活**：在会话里向指定 Agent 下发工作；执行走现有 Merak Session。
4. **看板收口**：待办可指派给 Agent，从看板进入对应会话跟进；不做一键 Run。

## 3. 信息架构

### 3.1 主导航（建议）

| 入口   | 职责                                      |
| ------ | ----------------------------------------- |
| 会话   | Agent 私聊列表与对话                      |
| 工作   | 看板事项（及轻量便签，可选）              |
| 通讯录 | Agent 花名册、创建入口、进入世界观 / 会话 |

现有「项目文件夹 → Session」能力保留；all-chat 作为并列工作模式或项目内子空间（实现阶段二选一，见 §7）。

### 3.2 核心实体

| 实体                   | 说明                                                    |
| ---------------------- | ------------------------------------------------------- |
| Agent（同事）          | 花名册条目；绑定世界观根目录与默认会话                  |
| World（世界观）        | 按 Agent 的文件夹树；容纳职责、规则、记忆、事实、决策等 |
| Conversation / Session | 与某 Agent 的私聊；底层为 Merak Session                 |
| WorkItem（看板事项）   | 独立于会话的待办；可指派 Agent；跟进方式为进入会话      |

## 4. 功能需求

### 4.1 Agent（同事）

| ID  | 需求                    | 验收要点                                                                    |
| --- | ----------------------- | --------------------------------------------------------------------------- |
| A-1 | 创建 Agent              | 填写名称、角色/一句话职责；创建后生成世界观目录骨架 + 可进入的默认会话      |
| A-2 | 通讯录列表              | 展示名称、角色、在岗摘要（可选）；可进入会话 / 世界观 / 简要配置            |
| A-3 | 职责即文件              | **不以独立 DB 字段作为唯一真相**；职责与工作说明写入世界观约定文件（见 §5） |
| A-4 | 删除 / 归档（可选本期） | 若做删除：需确认；世界观目录处理策略需明确（移入回收或保留）                |

**本期不做：** 每 Agent 独立 Skills/MCP 绑定 UI（先共用项目级 Skills/MCP）；Runtime 切换 UI。

### 4.2 世界观（核心）

世界观是 all-chat 的知识与约束中枢：**一切可用文件夹管理的长期内容**（职责、规则、记忆、事实、决策等）都落在此树下。

| ID  | 需求              | 验收要点                                                                        |
| --- | ----------------- | ------------------------------------------------------------------------------- |
| W-1 | 文件夹树          | 按 Agent 展示文件夹 / Markdown 文件；支持折叠、选中预览                         |
| W-2 | 新建文件夹 / 文件 | 可创建文件夹与 `.md` 文件；名称校验（非法路径字符拒绝）                         |
| W-3 | 编辑与保存        | Markdown 编辑；保存写磁盘；刷新 / 重启后内容仍在                                |
| W-4 | 搜索              | 按文件名与正文关键字过滤树                                                      |
| W-5 | 预置骨架          | 创建 Agent 时生成约定目录（§5.1）；可为空模板 + 简短说明头                      |
| W-6 | 与引擎打通        | 职责 / 规则 / 记忆按 §5.2 映射到 Merak 现有注入机制；开聊后模型行为体现约定内容 |
| W-7 | 可被工具读取      | 世界观位于工作区（或明确挂载路径）内，Agent 可用读文件工具访问事实/决策等       |

**本期不做：** 世界观内嵌权限审批、附件上传、主题。

### 4.3 会话

| ID  | 需求             | 验收要点                                                                                            |
| --- | ---------------- | --------------------------------------------------------------------------------------------------- |
| C-1 | Agent 私聊       | 从通讯录或会话列表进入；消息流式展示（复用现有 Chat）                                               |
| C-2 | 上下文绑定       | 该会话使用对应 Agent 的职责 / 规则 / 记忆作用域（§5.2）                                             |
| C-3 | 未读（可选）     | 列表可显示简单未读；**不做**独立通知中心                                                            |
| C-4 | 进入会话跟进事项 | 从看板事项可跳到该 Agent 会话，并可带上事项标题作为上下文提示（实现可用 composer 预填或系统短消息） |

**本期不做：** 附件；权限审批会话；通知会话；话题（Topic）子线程（若工期紧可后置）。

### 4.4 工作看板

| ID  | 需求     | 验收要点                                                        |
| --- | -------- | --------------------------------------------------------------- |
| B-1 | 创建事项 | 标题必填；可选指派 Agent、备注                                  |
| B-2 | 状态流转 | 至少：待办 → 完成；支持重新打开                                 |
| B-3 | 指派     | 可改指派 Agent；未指派视为个人事项                              |
| B-4 | 跟进     | 「去聊 / 跟进」进入会话；**文案与交互不得暗示「一键触发执行」** |
| B-5 | 持久化   | 重启后事项仍在                                                  |

**本期不做：** 任务 Run 生命周期抽屉、工具调用时间线、产物验证面板、手动「触发执行」。

### 4.5 工作辅助（可选，P1）

| ID  | 需求 | 说明                                   |
| --- | ---- | -------------------------------------- |
| N-1 | 便签 | 独立于会话的短文本增删改；可与看板同页 |
| N-2 | 日程 | 简易日程条目；非日历全家桶             |

## 5. 世界观目录约定与引擎映射

### 5.1 目录骨架（创建 Agent 时生成）

路径相对于项目或 all-chat 数据根（具体根路径实现阶段确定，需单一约定）：

```text
agents/<agentId>/
  PROFILE.md                 # 职责摘要（短）；通讯录/卡片主展示来源
  world/
    01-duty/                 # 职责与目标（详版工作说明）
      README.md
    02-rules/                # 规则与边界
      README.md
    03-memory/               # 长期记忆（用户偏好、反馈等）
      README.md
    04-facts/                # 项目事实
    05-decisions/            # 决策记录
```

说明：

- 文件夹**名称可本地化展示**（UI 显示「职责」「规则」「记忆」），磁盘可用稳定英文/编号前缀，避免重命名导致映射断裂。
- 用户可增删自定义文件夹；`01-duty` / `02-rules` / `03-memory` 为约定槽位，删除时需警告「可能影响自动注入」。

### 5.2 与 MerakCode 机制映射

| 世界观内容                     | MerakCode 落点                                                                        | 行为                                  |
| ------------------------------ | ------------------------------------------------------------------------------------- | ------------------------------------- |
| `PROFILE.md` + `01-duty/*`     | Custom Agent prompt（`.merakcode/agents/<id>.md`）和/或 Session system 拼接           | 开聊即带职责                          |
| `02-rules/*`                   | `.merakcode/rules/*.mdc`（建议 always 或按 agent 过滤）或 Session `instructions` 挂载 | 进入 Rule working-set                 |
| `03-memory/*`                  | 引擎 Memory 目录（`user` / `feedback` / `project` / `reference`）或等价写入           | 跨会话可回忆；可与自动 extract 协同   |
| `04-facts/*`、`05-decisions/*` | 工作区内普通 Markdown                                                                 | 主要靠读文件；重要结论可再写入 Memory |

**原则：** UI 管树与编辑；**认知生效**走引擎已有 agents / rules / memory / 读文件，不新建平行「假世界」仅存 SQLite、引擎读不到的实现。

### 5.3 与 Autera 旧模型差异

| Autera 现状                  | all-chat 要求                   |
| ---------------------------- | ------------------------------- |
| `world` 存在状态库中的虚拟树 | 真实目录 + UI 浏览编辑          |
| `brief` / `duty` 独立字段    | 合并为 `PROFILE.md` + `01-duty` |
| 多 Runtime Adapter           | 仅 MerakCode                    |

| ID   | 需求                                                                              |
| ---- | --------------------------------------------------------------------------------- |
| NF-1 | 本地优先；数据在本机项目或约定数据目录                                            |

| NF-5 | 不引入与本期无关的依赖膨胀；优先复用 `apps/desktop/renderer` 与 `packages/engine` |

## 7. 实现路线（建议）

### 7.1 产品落点

| 路线                               | 描述                                                                                  | 备注                         |
| ---------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------- |
| **推荐：Desktop 内 all-chat 模式** | 在 `apps/desktop/renderer` 增加会话 / 工作 / 通讯录；世界观文件树；Session 绑 agentId | 单一产品，长期维护成本低     |
| 备选：薄壳 + SDK                   | 外置壳只做花名册/看板/世界观编辑，执行全走 `@merakcode/sdk`                           | 适合快速验证；易与主产品分叉 |

本文档默认按**推荐路线**验收；若改走备选，§4 功能不变，仅交付形态变化。

### 7.2 分期

| 阶段 | 交付                                                                       | 依赖                         |
| ---- | -------------------------------------------------------------------------- | ---------------------------- |
| P0   | 目录约定 + 读写 API/服务；创建 Agent 骨架；世界观 UI；Agent 私聊绑定上下文 | 引擎 agents / rules / memory |
| P1   | 通讯录完善；工作看板 + 跟进跳转                                            | P0                           |
| P2   | 便签/日程；未读；规则/记忆更精细同步（.mdc 生成、memory 分类）             | P1                           |
| 以后 | 感知调度、每 Agent Skills/MCP、审批/通知、附件、多 Runtime                 | 明确单独立项                 |

### 7.3 关键复用（开发约束）

- **必须复用：** Session 消息与工具流、Custom Agent、Rules、Memory、Desktop Chat 组件、SDK（若壳分离）。
- **禁止本期重做：** 权限审批中心、通知中心、附件、Run 触发抽屉、主题引擎。

## 8. 验收清单（P0 + P1）

### 8.1 P0

- [ ] 可创建 Agent，磁盘出现 §5.1 骨架
- [ ] 世界观可新建文件夹/文件、编辑保存、重启仍在
- [ ] 修改 `PROFILE` / `01-duty` / `02-rules` / `03-memory` 后，新开与该 Agent 的会话能体现约定（人工抽检 prompt 或行为）
- [ ] 可从通讯录进入私聊并完成一轮正常问答（引擎真实或项目既有测试模型）

### 8.2 P1

- [ ] 看板可创建、指派、完成、重新打开
- [ ] 从事项「跟进」进入对应 Agent 会话
- [ ] 无「触发执行」入口；无权限审批/通知中心/附件/主题切换作为主路径

### 8.3 回归

- [ ] 现有项目 Session / 编码主路径不被破坏
- [ ] `pnpm check`（或约定子集）通过

## 9. 文案与交互约束

- 看板与会话的连接用语使用「去聊」「跟进」，避免「运行」「触发执行」「Start Run」。
- 世界观副标题建议：**「职责、规则、记忆与事实」**（与产品定义一致）。
- Agent 创建成功后的引导：先完善 `PROFILE` / 职责，再去聊。
